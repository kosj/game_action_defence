# 헌터 걷기 v3 — 부품 재사용 + 2관절 IK

## 적용한 방법

이전 시트 생성 방식은 양발의 교대와 시간적 일관성을 보장하지 못했다.
이번에는 상체·허벅지·정강이·방향별 신발을 한 번만 만들고, 고정된 부품을
관절로 변환하여 모든 프레임을 렌더링했다. 프레임별 이미지 생성과 보간 페이드는 없다.
상체·석궁의 윤곽과 색이 프레임마다 다시 그려지는 문제를 없앴다.

- 한 주기 0.96초, 양발 위상차 0.5주기, 24프레임 × 8방향.
- 발은 주기의 60% 동안 바닥에 접지한다. 접지 중 로컬 발 위치는 일정 속도로 후진한다.
- 바닥 이동 속도를 접지 발 속도와 일치시켜 접지 중 미끄러짐을 제거한다.
- 나머지 40%는 발을 들어 앞으로 보낸다. Hermite 곡선으로 이착지 속도를 연결한다.
- 무릎은 길이가 고정된 두 뼈의 기하학적 IK로 계산한다. 화면 투영 전에 3차원 좌표로 계산하여 8방향이 같은 보행을 공유한다.
- 상하 움직임도 주기 함수로 계산한다. 첫 프레임을 마지막에 복제하지 않는다.
- 좌우 방향은 같은 기준 부품을 반전해 외형 일관성을 유지한다.

근거:
- [Spine 공식 IK 설명](https://esotericsoftware.com/spine-ik-constraints): 발 목표로 다리 관절을 제어하고 바닥 관통을 방지하는 방식.
- [Godot 공식 2D skeleton 문서](https://docs.godotengine.org/en/stable/tutorials/animation/2d_skeletons.html): 부품 텍스처와 관절을 연결하는 2D 골격 구성.

여기서는 Spine 파일이나 유료 런타임을 사용하지 않는다. `gait.js`가 직접 관절을 계산하고 Canvas로 렌더링한다.

## 검증

`verify.mjs`가 2,000개 시점에서 다음을 확인했다:

- 항상 한 발 이상 접지, 발 높이는 0 이상.
- 두 다리의 뼈 길이가 고정됨.
- 0과 1주기 자세가 정확히 동일함.
- 반복 경계와 발을 떼는 순간의 좌우 속도가 허용 오차 내에서 이어짐.
- 접지 발의 속도와 바닥 속도가 일치함.

수치 결과는 `verification.json`에 있다. 이는 관절 궤적에 대한 검증이다.
최종 아트의 미적 완성도까지 보장하는 검사는 아니다. 브라우저 렌더 72프레임에서
페이지 오류가 없었고, GIF 프레임 수·투명 PNG 규격을 확인했다.
Godot 4.6.3에서 스크립트 구문 검사와 독립 씬 headless 로드를 수행했다.
씬 로드 때 시스템 인증서 저장소 경고가 있었으나 스크립트·씬 오류는 없었다.

## 재생성

1. 이 폴더에서 `python -m http.server 8765 --bind 127.0.0.1` 실행.
2. 브라우저에서 `http://127.0.0.1:8765` 열기.
3. `node verify.mjs`로 궤적 검사.
4. `RIG_NODE_MODULES`에 Playwright가 설치된 node_modules 절대 경로 지정 후 `node capture.mjs` 실행. Chrome 필요.
5. `python package_gifs.py` 실행. Pillow 필요. 렌더 결과를 GIF로 포장하며 그림을 수정하지 않는다.

`gait.js`의 SETTINGS에서 보폭, 발 높이, 주기를 조절한다.
게임 연결 시 시간만으로 재생하지 말고 실제 이동 거리로 위상을 진행해야 한다.
1주기 이동 거리는 `2 * reach / stance = 43.333...` 리그 단위이며, 시트 렌더 배율은 1.25이다.
화면 이동 거리를 `(43.333... * 1.25 * sprite_scale)`로 나눈 값을 위상에 더한다.

## 남아 있는 아트 특성

관절 부위가 보이는 컷아웃 스타일이며 망토·머리카락은 상체에 고정되어 있다.
이전 완성 캐릭터 그림을 그대로 분해한 것이 아니라, image_gen으로 기존 헌터를 참조해
리깅용 부품을 새로 제작했으므로 얼굴·의상 세부와 망토 길이는 원본과 차이가 있다.
걷기 구조는 결정적이고 반복 가능하다. 최종 아트 단계에서는 동일한 관절/피벗 규격으로
부품만 교체하거나 관절 가림과 망토 변형을 추가할 수 있다.

## 부품 생성

내장 image_gen 사용. 프레임 생성에는 사용하지 않았다.
`torso_parts.png`, `leg_parts.png`, `foot_parts.png`는 원본 생성 결과를 보존한다.
마젠타 배경은 미리보기의 런타임 크로마키 재질에서 제거하고 투명 시트로 렌더링한다.
프롬프트는 `prompts.md` 참조.
